# FinFlow

Личный учёт финансов. PWA, работает офлайн, синхронизируется между устройствами через Supabase.

Установка и деплой — в [SETUP.md](./SETUP.md).

---

## Что изменилось в этой версии

### Починено

**Кнопка «Начать» не работала.** `start()` в онбординге ждал `registerDevice()` — upsert в Supabase без таймаута, без `try/catch`, без индикатора. Любой запрос, не получивший ответа, подвешивал `await` навсегда, и кнопка выглядела мёртвой. Воспроизводилось стабильно: подвесить ответ от `/rest/v1/devices` — экран не переключается. Теперь каждый сетевой вызов обёрнут в `withTimeout`, онбординг не ходит в сеть вообще, а любое исключение показывается пользователю.

**Перевод падал с TypeError.** Для `type = 'transfer'` в справочнике не было ни одной подходящей категории, `selCat` получался `undefined`, и `selCat.id` ронял сохранение. Добавлена служебная категория перевода, и переводы больше не требуют выбора категории.

**Перевод терял деньги.** Списывал с одного счёта и не зачислял на второй, а выбора второго счёта в интерфейсе не было вовсе.

**Правка и удаление операции не трогали баланс.** Изменили сумму — расхождение оставалось навсегда.

**Экран целей был недостижим.** Его не было в навигации, а единственная ссылка на него показывалась по условию `goals.where('isArchived').equals(0)`, который всегда возвращал пусто: IndexedDB не индексирует boolean. Все флаги переведены в `0/1`.

**Цели, бюджеты, правки и удаления счетов не синхронизировались** — они просто не попадали в очередь отправки, и ближайший `pull` откатывал их обратно.

**Копейки терялись при отображении**, а деньги хранились как float.

**Сдвиг времени при редактировании**: ISO-строка подставлялась в `datetime-local` без перевода в локальную зону, дата ползла на величину часового пояса при каждом открытии.

**База была открыта наружу.** RLS-политики стояли как `for all using (true)` — любой, кто открыл сайт и взял anon-ключ из бандла, получал полный доступ ко всем финансовым данным.

### Архитектура

**Баланс не хранится.** Есть `openingBalance` счёта и журнал проводок (`postings`). Баланс = `openingBalance + Σ postings`. Операция создаёт одну проводку (расход/доход) или две (перевод). Правка пересобирает проводки, удаление их снимает. Рассинхронизировать баланс структурно невозможно — именно поэтому четыре бага выше не могут вернуться.

**Деньги в копейках**, целым числом. `0.1 + 0.2` больше не участвует.

**Синхронизация** — очередь с ретраями и dead-letter (пять неудач → запись помечается и показывается в настройках, а не блокирует счётчик вечно). `pull` инкрементальный по `updated_at`, с постраничной выборкой (прежний лимит в 500 операций снят), не перезаписывает локальные записи, если они свежее или по ним есть неотправленные изменения. Удаления едут tombstone'ами.

**Авторизация** — Supabase Auth, email + пароль. Хэширование на сервере, на клиенте только JWT, RLS по `auth.uid()`. При входе под другим аккаунтом локальная база очищается, чтобы не смешать две истории.

### Добавлено

- **Счета**: дебетовые, кредитки (лимит и доступная сумма), наличные, накопительные, вклады (ставка, капитализация, прогноз на дату окончания).
- **Сверка с банком**: расхождение записывается операцией-корректировкой, которая не искажает статистику, и сохраняется в историю сверок.
- **Аналитика**: норма сбережений, запас прочности (на сколько месяцев хватит денег), обязательные vs остальные траты, прогноз на конец периода, динамика по категориям к прошлому периоду, бюджеты с календарным темпом, шесть месяцев доходов и расходов, накопительная кривая, детектор подписок, подсветка аномалий.
- **Навигация по периодам** — прошлые месяцы наконец открываются.
- **Цели**: привязка к счёту (прогресс = реальный баланс), пополнение настоящим переводом, требуемый и фактический темп, прогноз даты достижения, цель-подушка с суммой из ваших же расходов.
- **Экспорт** CSV и JSON.
- **ErrorBoundary** и логирование необработанных промисов — белый экран без следов больше не повторится.

## Структура

```
src/

    index.ts        Dexie: схема v3 + миграция с v2

    supabase.ts     клиент + withTimeout
    categories.ts   справочник категорий

    money.ts        копейки

  components/
    screens/        экраны

    ErrorBoundary.tsx
tests/              проверки бухгалтерии и миграции
```

## Что осталось за рамками

Мультивалюта и курсы. Полная двойная запись со счетами доходов/расходов. Импорт банковских выписок и MCC-коды. Сканер QR-чеков. Нормализованные мерчанты. Регулярные платежи с автосозданием. Долги и графики погашения. Sankey-диаграмма. Светлая тема.

Структура данных под них подготовлена: проводки — это уже половина двойной записи, добавление валюты на счёт не ломает ядро.

## Вход
Регистрации и писем в приложении нет. Пользователь создаётся вручную: Supabase → Authentication → Users → Add user → Create new user (email + пароль, галочка Auto Confirm User). Затем в Authentication → Sign In / Providers выключить Allow new users to sign up.
Вход нужен, потому что строки в БД защищены RLS по `user_id`.
